1. RESUMO EXECUTIVO
-------------------

O FateFlow é um tracker de animes com uma interface inspirada em um arquivo mágico/centro de comando. A aplicação permite ao utilizador:

- Ver um dashboard com o progresso geral.
- Continuar a obra atual.
- Acompanhar progresso por episódio ou filme.
- Ver o estado de cada obra.
- Consultar a própria rota de visualização.
- Pesquisar e filtrar o catálogo.
- Alternar entre catálogo em lista e mapa visual.
- Consultar histórico de atividade.
- Alterar algumas preferências.
- Abrir um painel/modal de detalhes de cada obra.

A interface já está funcional para demonstração e uso individual no mesmo navegador. O principal ponto incompleto é que o progresso atual é guardado somente em localStorage; a base de dados e o sistema de autenticação ainda não estão ligados às funcionalidades do utilizador.

Classificação atual:

- Interface: MVP avançado.
- Navegação: funcional.
- Responsividade: funcional para desktop e mobile.
- Progresso local: funcional.
- Persistência entre dispositivos: ainda não implementada.
- Autenticação real: ainda não integrada à experiência do utilizador.
- Catálogo de produção: ainda incompleto.
- Deploy em VPS/domínio: ainda por fazer.
- Produto 100% produção: ainda não.

8. DEPLOY NA VPS — GUIA BASE
----------------------------

Os dados reais da VPS, domínio, utilizador SSH e credenciais não estão presentes neste ficheiro e nunca devem ser inventados. Substituir os placeholders abaixo.

Variáveis a definir no servidor:

- NODE_ENV=production
- PORT=3000 ou a porta interna escolhida
- DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/DATABASE
- OAuth/Manus variables exigidas pelo starter, caso o login seja mantido
- Outras variáveis presentes no .env.example do zip

Passos gerais:

1. Copiar o zip para a VPS ou clonar o repositório.
2. Extrair para um diretório como /var/www/fateflow.
3. Confirmar que package.json, pnpm-lock.yaml e código estão presentes.
4. Instalar Node.js 22.
5. Instalar pnpm 10.18.0.
6. Criar .env de produção com permissões restritas.
7. Executar pnpm install --frozen-lockfile.
8. Executar pnpm db:migrate depois de validar o DATABASE_URL.
9. Executar seed idempotente, quando criado.
10. Executar pnpm check.
11. Executar pnpm build.
12. Testar manualmente com PORT=3000 pnpm start.
13. Confirmar curl http://127.0.0.1:3000/api/health.
14. Criar serviço systemd apontando para pnpm start ou para node dist/index.js.
15. Configurar Nginx ou Caddy para encaminhar o domínio para 127.0.0.1:3000.
16. Configurar DNS A/AAAA para o IP da VPS.
17. Configurar TLS.
18. Testar o domínio em desktop e mobile.

Exemplo de systemd, adaptar ao ambiente real:

[Unit]
Description=FateFlow Anime Watch Tracker
After=network.target

[Service]
Type=simple
User=fateflow
WorkingDirectory=/var/www/fateflow
EnvironmentFile=/var/www/fateflow/.env
Environment=NODE_ENV=production
Environment=PORT=3000
ExecStart=/usr/bin/node /var/www/fateflow/dist/index.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

Comandos típicos depois de criar o ficheiro systemd:

- sudo systemctl daemon-reload
- sudo systemctl enable fateflow
- sudo systemctl restart fateflow
- sudo systemctl status fateflow
- journalctl -u fateflow -f

Exemplo Nginx, adaptar o domínio e certificados:

server {
    listen 80;
    server_name SEU_DOMINIO.com www.SEU_DOMINIO.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

Depois:

- Testar nginx -t.
- Recarregar nginx.
- Executar certbot ou configurar TLS equivalente.
- Confirmar que o proxy preserva cookies e headers necessários ao login.


9. CUIDADOS IMPORTANTES DE PRODUÇÃO
------------------------------------

- Não usar localStorage como fonte de verdade depois de ativar contas.
- Não confiar no userId enviado pelo browser; extrair do utilizador autenticado no servidor.
- Validar todas as mutations com zod.
- Não expor DATABASE_URL no frontend.
- Não colocar segredos no repositório ou no zip.
- Fazer backup antes de migrations destrutivas.
- Não usar DELETE de dados em testes contra a base de produção.
- Seeds devem ser idempotentes.
- Não apagar users, migrations ou dados existentes durante o setup.
- Configurar cookies de sessão corretamente para HTTPS e domínio final.
- Se houver iframe/Preview, cookies precisam de SameSite=None e Secure conforme o ambiente.
- Usar HTTPS obrigatório em produção.
- Não assumir que a imagem de referência pode ser distribuída publicamente sem validar direitos.
- Não prometer sincronização entre dispositivos antes de ligar o backend.
- Não chamar recomendações de IA de “inteligentes” se forem apenas regras fixas; separar recomendação determinística de recomendação por IA.

--------------------------------

O próximo agente deve entregar:

1. Um utilizador capaz de entrar na aplicação.
2. Um utilizador capaz de escolher uma rota.
3. Um utilizador capaz de marcar episódios e filmes.
4. O progresso visível em qualquer dispositivo depois de novo login.
5. Um histórico persistente.
6. Uma recomendação correta baseada no estado real.
7. Um catálogo completo e administrável.
8. Uma aplicação servida no domínio real com HTTPS.
9. Uma base de dados com migrations e backup.
10. Testes que protejam o cálculo de progresso e o isolamento de dados.

Até esses pontos serem concluídos, o FateFlow deve ser tratado como MVP/preview funcional, não como produto final de produção.
